# Domain Docs

## Before exploring, read these

- `CONTEXT.md` at the repo root.
- `docs/adr/` for decisions touching the area being explored.

## Use the glossary's vocabulary

When naming a domain concept in an issue, plan, refactor proposal, or test, use the term defined in `CONTEXT.md`. Do not drift to synonyms explicitly avoided by the glossary.

If a needed concept is missing from the glossary, treat it as a domain-modeling gap and resolve it before introducing the term.

## Flag ADR conflicts

If proposed work contradicts an existing ADR, surface the conflict explicitly rather than silently overriding it.

## Layout

This repository uses a single context:

- `CONTEXT.md`
- `docs/adr/`
