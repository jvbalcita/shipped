# Follow + activity feed with read-time assembly

Members follow creators (users) and projects through a polymorphic `follows` table that mirrors the cheers pattern (ADR 0003): `Followable`/`Follows` concerns, a unique `(user_id, followable_type, followable_id)` index, and explicit per-target routes (`/users/{user}/follow`, `/projects/{project}/follow`) rather than a single endpoint validating a `followable_type` allowlist — route binding gives us typed controllers and clean Wayfinder helpers for free. Follows are deliberately public (count + follower identities), matching the integrity-first stance of the registry: shipping in public is the product. Self-follow is denied by policy; following your own project is allowed without a special case.

Feed events (`launched`, `released`, `reviewed`, `cheered`, `verified`) are written to an append-only `activities` log by model observers through a single `ActivityRecorder` service that dedupes on (actor, verb, subject, occurred_at), plus a fire-once guard on (verb, subject) for `launched` so re-verifications after failure record a fresh `verified` without ever duplicating the launch. The subject of every activity is the project itself — not the release or review — so the read-time feed query is exactly one index-friendly statement (actions by followed creators ∪ events on followed projects) and dedupe is free because an event is one row. Release specifics (title, id) and review ratings travel in the `meta` JSON column. The scheduled release publisher now saves per model instead of bulk-updating so first-public launches are observed.

The feed is assembled at read time with no fan-out: follower counts today do not justify precomputed timelines, and a single query with `whereIn` subselects stays cheap on the `occurred_at` index. Scheduled releases carry a future `occurred_at` (the publish instant, not the scheduling instant) and the feed filters them until due — so a release "fires" only when it actually publishes, without a queue. When follower volume makes the union query slow, fan-out into per-follower timelines is the escape hatch, and the activities log already has the right shape for it.
