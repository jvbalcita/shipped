# Adopt Ship Stories as the creator value wedge

Shipped will model one creator-approved Ship Story per Project as the durable public explanation of what was built and why. The existing Project description becomes the story's short overview, while structured story content lives in a first-class record, remains private until complete, and is publicly available only while its Project is discoverable. Releases remain separate chronological shipping events and provide the primary return path for creators.

## Considered Options

- Keep the current freeform Project description as the complete story: rejected because it does not reliably produce the structured context or shareable value that differentiates Shipped from a directory.
- Treat every Release as the story: rejected because Releases describe subsequent shipping events and should not replace the stable narrative of a Project.
- Build a larger feed, ranking system, or feedback marketplace: deferred because those features depend on community density and do not give an individual creator immediate value.

## Consequences

- Public discovery gains a consistent, creator-approved narrative and a shareable Project artifact.
- Creators can return by publishing another Release or adding another public Project without rewriting the original story.
- Public visibility and share assets must follow the Project's current Verification State and removal rules.
- Existing Projects need draft stories backfilled from their current description and first Release, with creator approval before the new story/card is considered complete.
