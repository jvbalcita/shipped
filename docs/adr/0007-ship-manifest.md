# Ship Manifest — collectible SVG launch card

Every discoverable launch serves a collectible "ship manifest" at `GET /manifests/{creator}/{project}.svg`: a fixed 1200×630 self-contained SVG in the Swiss print system — wordmark header, hero name and tagline, crew line (creator + top-3 stack tags), a docket row with the launch date and DISPATCH serial, a LIVE ON CLOUD stamp (previously VERIFIED LIVE) with the verification date, a first-cheer line when one exists, and a footer wordmark. It reuses the OG card engine pattern (Blade view, `image/svg+xml`, no external assets) so there is zero new infrastructure, and every value is pulled live from the project record — the manifest is derived data, never stored state.

Privacy and caching match the OG images and the README badge exactly: non-discoverable projects 404 so a manifest URL never leaks a private launch, and responses carry `Cache-Control: public, max-age=300`. The launch date prefers `launch_date`, falling back to `filed_at`, then `created_at`; the first cheer is the earliest cheer on the project. The first-cheer line renders only when a cheer exists — an empty manifest section is worse than an absent one.

The public launch page links to the manifest with a Save manifest button (a plain anchor with a `download` attribute, so the browser saves the SVG directly) plus a copy-link affordance with a toast. The URL is exposed as a page prop only when the project is discoverable, keeping the button honest with the endpoint's 404 rule — a creator previewing a private draft sees no manifest action. Raster (PNG/JPEG) export is deliberately out of scope for v1; SVG screenshots and embeds cover the sharing loop without a rasterization service.
