# Self-hosted README verification badge

Every verified launch serves a two-segment Swiss print badge at `GET /badges/{slug}.svg` — left segment the black SHIPPED wordmark, right segment the live verification status (VERIFIED LIVE green, STALE amber, VERIFICATION FAILED red, UNVERIFIED gray). The badge is self-hosted SVG rendered through a Blade view, reusing the OG card engine pattern: no shields.io dependency (design control and cache behavior stay with Shipped), no external assets in the SVG, and the same privacy rule as OG images — non-discoverable projects 404 so a badge URL never leaks a private launch's existence. Responses carry `Cache-Control: public, max-age=300`, matching the cover plate: fresh enough to track verification changes within minutes, cheap enough to sit in every README on GitHub's CDN.

The markdown snippet is built server-side in the Studio project edit page from named routes (never a hard-coded host), so it is domain-agnostic across environments; the badge image links to the public launch page, closing the badge → harbor loop. The snippet only appears when the project is publicly discoverable — a snippet for a private project would render as a broken image in a README anyway. Status rendering deliberately covers all four `verification_status` values even though only verified projects are normally discoverable: demo projects exercise the other states locally, and the mapping future-proofs the SVG if the discoverable rule ever relaxes.
